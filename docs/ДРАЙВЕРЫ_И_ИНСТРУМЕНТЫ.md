# Драйверы и инструменты

## Serial

Serial driver используется ядром для диагностики и текстового вывода. Частые `printf` из syscall, IRQ или IPC loops заметно меняют timing и могут влиять на наблюдаемую отзывчивость. Диагностический вывод на горячем пути следует отключать после локализации проблемы.

## PIT и scheduler

PIT channel 0 формирует системные ticks. Частота задана `PIT_TARGET_HZ` в `kernel/drivers/pit/pit.h`. IRQ0 увеличивает счётчик и запускает scheduler accounting/preemption. Слишком высокая частота увеличивает overhead обработчиков; слишком низкая ухудшает отзывчивость блокирующих ожиданий.

## PS/2

PS/2 driver обслуживает клавиатуру и мышь. IRQ handler переводит scancodes в ASCII или отрицательные коды специальных клавиш и складывает события в input queue. TTY focus направляет обычные печатные клавиши терминалу; desktop получает события через `SYS_INPUT_POLL`.

## NVMe и block devices

NVMe-драйвер регистрирует block devices; FAT32 и block cache используют общий block-device интерфейс. Настройки NVMe находятся в ветке `DRIVERS/nvme` реестра.

## Сборочные инструменты

- `make -j2` собирает kernel ELF и ISO.
- `bash user/build.sh` собирает user ELF в `build/user/`.
- `make install-user-programs` собирает user ELF и устанавливает их в `disk.img` с помощью loop mount и sudo.
- `make run-kvm` запускает QEMU/KVM с ISO и `disk.img`.
- `tools/hivegen.py` создаёт registry hive из INI.

`compile_commands.json` предназначен для clang tooling. `.clang-tidy` содержит правила анализа; замечания анализатора не обязательно являются ошибками сборки.

## Известные незавершённые места

- Регулярное чтение FAT32 каталога по индексу повторно сканирует каталог.
- Некоторые конфигурационные поля объявлены в `SystemConfig`, но ещё не используются всеми подсистемами.
- GUI client API и серверные input/update сценарии развиваются; приложения могут иметь неполные действия кнопок.
- Не все ошибки драйверов приводят к автоматическому восстановлению.
