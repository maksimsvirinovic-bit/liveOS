# Архитектура LiveOS

## Общая схема

LiveOS загружается в 64-разрядный long mode через UEFI MyLoader. Ядро подготавливает CPU, память, драйверы, файловые системы и framebuffer, после чего создаёт shell и, если включён `desktop_autostart`, отдельный процесс `DESKTOP.ELF`.

Система разделена на три уровня:

1. Ядро владеет аппаратурой, адресными пространствами, процессами, файловыми системами и syscall ABI.
2. Desktop-процесс владеет framebuffer, композицией окон, taskbar, hit-testing и серверной частью оконного IPC.
3. GUI-приложения запускаются отдельными ELF-процессами и обращаются к desktop через сообщения `USER_WINDOW_MSG_*`.

Desktop не должен запускать вторую графическую root-сессию внутри клиента. Все клиентские окна создаются в едином `GuiDesktop` compositor.

## Структура исходников

| Путь | Назначение |
|---|---|
| `EFI/edk2/` | UEFI-загрузчик MyLoader и его сборка |
| `kernel/core/` | Инициализация ядра и стартовых процессов |
| `kernel/arch/x86_64/` | GDT/TSS/IDT, IRQ, syscall entry, per-CPU |
| `kernel/mm/` | Paging, VMA, PMM, heap, user ABI |
| `kernel/tasking/` | Process, fork/exec/exit, scheduler, переключение контекста |
| `kernel/filesystems/` | VFS, FAT32, regfs, tmpfs, block cache |
| `kernel/drivers/` | PIT, PS/2, serial, NVMe и прочие драйверы |
| `kernel/elf_loader/` | ELF64 сегменты и символы |
| `user/sys.h` | Пользовательские syscall-обёртки и оконный IPC контракт |
| `user/desktop/` | Desktop compositor, GUI primitives, renderer, window server |
| `user/desktop/apps/` | Отдельные GUI ELF-клиенты |
| `tools/` | Генерация registry hive |

## Порядок запуска

`kmain()` в `kernel/core/main.c` инициализирует драйверы, CPU, память, PCI/NVMe, VFS, framebuffer, PS/2 и PIT. Затем монтируется FAT32 в `/` и hive registry через regfs в `/reg`. Shell загружается из `default_shell`; desktop загружается из `/bin/DESKTOP.ELF`, если `desktop_autostart` включён. При неудаче используется fallback shell.

Настройки ядра и пользовательской среды загружаются из `SYSTEM.HIV`. Исходные данные генератора находятся в `tools/SYSTEM.ini`.

## Архитектурные ограничения

- Графический вывод работает через CPU framebuffer и backbuffer; аппаратный GPU backend отсутствует.
- Desktop использует framebuffer mapping, поэтому полный `render_present()` копирует весь экран. При изменениях нужно коалесцировать кадры и по возможности использовать dirty rectangles.
- Window IPC имеет ограниченную очередь. События ввода, close и ответы должны потребляться, а повторяемые обновления элементов интерфейса — объединяться.
- Некоторые GUI приложения пока реализованы частично: наличие отдельного ELF не означает полноценную обработку всех контролов и команд.
- UEFI loader является отдельным проектом внутри `EFI/edk2`; не следует смешивать его build artifacts с kernel/user source changes.
