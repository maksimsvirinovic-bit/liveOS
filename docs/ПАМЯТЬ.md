# Управление памятью

## Paging и адресные пространства

x86_64 page tables управляются в `kernel/mm/paging.c`. Основные значения и flags описаны в `paging.h`: страница равна 4096 байтам; присутствуют P/W/U, NX, huge-page и cache flags. `paging_switch()` загружает физический адрес PML4 в CR3 и добавляет kernel-half mappings в пользовательские таблицы.

Виртуальные области ядра заданы константами:

- direct physical map начинается с `PHYS_MAP_BASE`;
- vmalloc располагается в диапазоне `KERNEL_VMALLOC_BASE`;
- kernel heap расположен в `KERNEL_HEAP_BASE`.

Физические адреса переводятся в direct map через `phys_to_virt`; это макрос адресного преобразования, а не отображение пользовательского процесса.

## Physical memory и heap

PMM выделяет физические страницы и учитывает reference count для совместно отображённых страниц. Kernel heap используется для небольших объектов, VMA, процессов, файловых структур и временных буферов. Большие непрерывные kernel ranges резервирует vmalloc.

Освобождение address space должно сначала снять ссылки на пользовательские физические страницы, затем освободить page-table pages, VMA metadata и PML4. Framebuffer и общие ABI pages имеют отдельное владение и refcount semantics.

## VMA и user layout

VMA — связный список диапазонов в `kernel/mm/vma.c`. Типы включают anonymous/file/stack/ABI/framebuffer/backbuffer. VMA описывает назначение и права диапазона, но сама по себе не гарантирует, что каждая страница уже физически отображена.

Базовые user ranges объявлены в `kernel/mm/vmm.h`:

- ABI page: низкий адрес около `USER_ABI_BASE`;
- ELF code: обычно начинается с `0x400000`;
- heap: диапазон `USER_HEAP_BASE..USER_HEAP_LIMIT`;
- stack: верхняя граница `USER_STACK_TOP`, размер `USER_STACK_SIZE`.

При `exec` создаётся новый `AddressSpace`, маппится user stack и ABI page, затем ELF loader отображает сегменты по program headers.

## COW и page faults

Fork может помечать writable pages как copy-on-write. При write fault обработчик `pf.c` проверяет VMA и COW flag, выделяет новую страницу, копирует содержимое и устанавливает writable mapping.

Page fault handler также распознаёт kernel stack guard и user stack guard. Demand/lazy allocation поддержана не для всех видов VMA: сообщение о lazy alloc указывает, что адрес находится внутри VMA, но PTE отсутствует и обработчик не создал страницу.

## Framebuffer и backbuffer

Framebuffer отображается в kernel virtual address через uncached mapping. Desktop получает user mapping через framebuffer syscall и создаёт отдельный anonymous backbuffer. `render_present()` копирует backbuffer в framebuffer; это CPU-копирование, без GPU acceleration.

Cursor и drag могут обновлять dirty regions, но корректность зависит от восстановления фона под старым положением объекта и включения drop shadow в границы обновления.
